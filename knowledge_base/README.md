## Record schema

```jsonc
{
  "id": "<source-type-prefix>.<n>",
  "source": { "type": "...", "file": "...", "date": "YYYY-MM-DD", ...extra },
  "content": {
    "text": "<full transcript, reply, or post text, verbatim>",
    "language": "english | hinglish | hindi | urdu | null",
    "question": "<for qa/dm pairs; null otherwise>",
    "question_language": "..."
  },
  "classification": {
    "domain": "professional",
    "topics": ["..."],                  // matched from a fixed keyword lexicon
    "knowledge": true,                  // carries transferable knowledge
    "experience": bool,                 // personal-history heuristic
    "opinion": bool,                    // opinion/recommendation heuristic
    "style": bool,                      // stylistic/persona signal
    "ai_assisted": bool
  }
}
```

## Rules applied

- **Verbatim.** Text preserved exactly (only full-record duplicates removed).
- **Conversations.** Question and reply kept as separate fields on one record.
- **No translation.** Language detected by script: Devanagari → `hindi`,
  Arabic-script → `urdu`, romanized Hinglish markers → `hinglish`, else `english`;
  `null` for emoji-only replies.
- **Classification.** Transcripts/comments/DMs: `knowledge=true, style=true,
  ai_assisted=false`. LinkedIn posts: `knowledge=true, style=false,
  ai_assisted=true` (written by AI). Domain is `professional` everywhere
  (per source-data `domain` field). `experience`/`opinion` are conservative
  regex heuristics over reply + question.
- **Excluded.** `*_filtered.json` (25 comment + 7 dm) — DM-deflection replies
  ("check dm"), no content. Whitespace-only records. Duplicate transcripts
  (`aws/day-9-i.txt`↔`aws/aws-ami.txt`, `questions/VID_20260520_002139_621*`
  ↔`VID_20260520_232113_881*`) and duplicate LinkedIn texts (first retained).

## Notes

- Transcript `date` is the file modification date (transcripts carry no own
  date); qa/dm/linkedin dates are from source `date` (unix-ts and string forms
  normalized to `YYYY-MM-DD`).
- `topics` come from a small keyword lexicon matched against text; ~1100 short
  style replies have empty `topics` (not invented).
- Style-only replies (`value_type: style_only` in source) are included — short
  or emoji replies are still style/persona signals.
